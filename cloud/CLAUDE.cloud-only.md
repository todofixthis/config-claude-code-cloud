# Maintaining this file

`cloud/CLAUDE.md` is generated by `cloud/generate-claude-md.sh` — never edit it directly, since regeneration overwrites it. The script concatenates this file (cloud-only content) with `cloud/CLAUDE.shared.md` (content shared with `todofixthis/config-claude`).

Editing cloud-only content: change this file. Editing shared content: this repo is `cloud/CLAUDE.shared.md`'s canonical home — it's public, so both this repo's own generation and `todofixthis/config-claude`'s fetch of it work without auth — so change it here, not there.

Either way: run `cloud/generate-claude-md.sh`, commit `cloud/CLAUDE.md`, and push. Then bump the version comment in `cloud/pointer.sh` and re-paste `pointer.sh`'s content into the environment's Setup script field, to apply the change immediately rather than waiting for the ~7-day cache cycle. `setup.sh` is unaffected — it still fetches `cloud/CLAUDE.md` as one file; this split only changes how that file is built.

Changed `cloud/CLAUDE.shared.md`? `todofixthis/config-claude`'s `generate-claude-md.sh` fetches it from GitHub, so it only picks up the change once this repo's push has landed. After pushing here: in a `todofixthis/config-claude` checkout, run its `generate-claude-md.sh`, then commit and push there too.

Locally, `~/.claude/CLAUDE.md` is symlinked to `todofixthis/config-claude`'s checkout, not this repo's — that repo's `CLAUDE.md` is generated the same way, from its own local-only fragment plus this repo's `cloud/CLAUDE.shared.md`.

A cloud session editing `~/.claude/CLAUDE.md` in place — `phx:reflection` deciding to record a new pattern, say — is editing the fetched copy: invisible everywhere else, and gone at the next cache rebuild. Make the edit in whichever source file above it belongs in instead.
